# B40 — nothing detected that `Package.resolved` had drifted from the manifests

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

`Package.swift` and `Package.resolved` are two statements about the same dependency graph, and CI
used the lockfile only as a cache key. Adding a dependency, or re-ranging one, without regenerating
the lockfile left the two disagreeing: the build silently resolves a graph nobody reviewed, and the
rewrite of `Package.resolved` appears as an unrelated diff later, or not at all in a clean checkout.

## Fails-before evidence

A drifted lockfile — here `swift-nio` claiming 2.101.0 with a zero revision — is repaired by
`swift package resolve`, which is exactly the silent rewrite that should be a failure:

```
$ <resolve>
$ git diff --exit-code -- Package.resolved
GATE FAILED (drift caught) — exit non-zero
```

The gate is the pair of commands; before this change nothing ran them, and the drift would have
surfaced only as an unexplained `Package.resolved` change on somebody else's machine.

## The fix

A `Lockfile matches the manifests` step in the `build-and-test` job, before the build:

```yaml
- name: Lockfile matches the manifests
  run: |
    set -euo pipefail
    swift package resolve
    if ! git diff --exit-code -- Package.resolved; then
      echo "::error::Package.resolved is out of date; run 'swift package resolve' and commit it"
      exit 1
    fi
```

It runs after the cache step (so resolution happens against the cached graph) and before the build
(so the failure is reported before minutes of compiling). Placing it in this job rather than
`static-analysis` is deliberate: this is the job that already has the SwiftPM cache.

## Verification

Local equivalent of the step (the only difference is `--scratch-path`, which keeps the build tree
out of the Dropbox-synced repository — the same reason every local SwiftPM command in this audit
passes it):

```
$ swift package resolve --scratch-path $SCRATCH && git diff --exit-code -- Package.resolved
no drift today (exit 0)

$ <drift the lockfile, resolve again> && git diff --exit-code -- Package.resolved
GATE FAILED (drift caught) — exit non-zero
lockfile restored
```

`git diff` after restoring confirms `Package.resolved` is byte-identical to `HEAD`. The workflow
still parses as YAML (12 steps in `build-and-test`), and the dispatched run on the branch exercises
the step for real.
