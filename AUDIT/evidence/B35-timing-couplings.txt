# B35 — timing couplings in the orchestrator tests

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

Three separate couplings, listed by the finding:

1. **A dead sleep standing in for synchronisation.** `testOpenCircuitBreakerSkipsTheProviderWithoutCallingIt`
   slept 60 ms with the comment "the state update happens in a detached task inside
   `recordFailure`". `ProviderHealth.recordFailure` has awaited the breaker before returning since
   the B-series reliability work (and `FusionAndReliabilityTests` asserts exactly that), so the
   sleep did nothing — and the comment invited a reader to reintroduce the race it described.
2. **A wall-clock upper bound with a 6× margin.** The time-budget test asserted the whole call
   finished in under 2 000 ms when the budget under test is 300 ms, which measures the CI runner's
   scheduler as much as the sentinel.
3. **A stated rule that was not written down.** `HTTPTransportTests` says "50 ms is the longest
   sleep this suite permits", while other files deliberately wait longer (a real refill, a real
   transport delay). The rule was true only for the file that stated it.

## Fails-before evidence

The dead sleep is provably dead: with it deleted the test passes immediately and its breaker
assertions still hold.

```
$ swift test --filter testOpenCircuitBreakerSkipsTheProviderWithoutCallingIt
Test Case ... passed (0.001 seconds)          # was 0.061 s+, the sleep was the only difference
```

Nothing else in the test changed, and `FusionAndReliabilityTests.testOutcomesReachTheBreakerBeforeRecordReturns`
independently asserts the ordering the comment used to deny.

## The fix

* The sleep and its stale comment are gone, replaced by a comment that states what is actually
  true and points at the test that pins it.
* The budget test now asserts the contract first — the responsive provider's results survive and
  the hang is reported with the `.timeout` category — and keeps only a loose 10 000 ms bound whose
  job is to catch a sentinel that never fires at all (the stub hangs for 60 s). The bound no longer
  claims to measure the budget.
* The throttle test is **kept** with a real clock, which is what the finding allows: the point of
  that test is that a real token-bucket refill is waited out, and it asserts the observable
  contract (`callCount == 1`, one result, no failures) rather than the elapsed time.
* The sleeping rule is now stated where it applies, in the wiki's testing page, in the form the
  suite actually follows: tests synchronise on awaited calls, a real clock is used only where a
  real delay is the subject, and those waits are bounded by a race or a lower bound rather than a
  tight upper bound.
