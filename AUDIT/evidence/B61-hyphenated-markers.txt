# B61 — hyphenated boilerplate markers could never match

Host: this Mac (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

```swift
let tokens = identifier.split(whereSeparator: { !$0.isLetter && !$0.isNumber }).map { String($0) }
for token in tokens where token == needle
    || (token.count > needle.count && token.hasPrefix(needle)
        && token.dropFirst(needle.count).first == "-")
```

Splitting on *every* non-alphanumeric character removed hyphens as well, so `class="side-bar"`
became `["side", "bar"]`: neither token could equal the `side-bar` marker, and the third conjunct —
which looks for a hyphen after the marker — was unreachable, because a token produced this way can
never contain one. Every hyphenated marker in the list was dead: `side-bar`, `skip-link`,
`meta-bar`, `site-header`, `site-footer`, and the hyphenated part of any BEM-ish name.

## Fails-before evidence

```
$ swift test --filter testHyphenatedBoilerplateMarkersAreRemoved
error: ... XCTAssertFalse failed - Chrome text that must not survive.
```

The `<div class="side-bar">` and `<div class="site-header">` blocks were kept in the extracted text.

## The fix

Hyphens survive tokenisation, and a marker matches as a whole token or as a hyphen-delimited part:

```swift
let tokens = identifier.split(whereSeparator: { !($0.isLetter || $0.isNumber || $0 == "-") })
...
for token in tokens
where token == needle || token.hasPrefix(needle + "-") || token.hasSuffix("-" + needle)
```

`side-bar`, `side-bar-inner` and `wrapper-side-bar` are chrome; `sidebar` and `side` are not
matched by `side-bar` (the marker list has its own `sidebar` entry). The old behaviour for
unhyphenated names is unchanged: `navigation-bar` matched before (as `navigation`) and matches now
(as `navigation-…`).
