# B11 — a half-open breaker authorised an unbounded number of requests

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

`ProviderHealth.authorize` branched on the breaker *snapshot* taken one `await` earlier and only
honoured the breaker's answer inside the `.open` branch:

```swift
if snapshot.state == .open {
    let allowed = await breaker.shouldAttempt()
    if !allowed { return ProviderFailure(..., category: .circuitOpen, ...) }
} else {
    _ = await breaker.shouldAttempt()          // <- refusal discarded
}
```

`CircuitBreaker.shouldAttempt()` owns the single-probe invariant: in `.halfOpen` it returns
`true` for the caller that claims the probe and `false` for everyone else
(`CircuitBreaker.swift:85-95`). Discarding that answer meant every caller that arrived while the
probe was in flight was admitted, so a provider recovering from a failure took the whole
concurrent fan-out instead of one request — exactly the hammering the half-open state exists to
prevent.

## Fails-before evidence

Against pristine `HEAD` (`fa6681f`, fix reverted from the source only, test kept):

```
$ swift test --filter testHalfOpenBreakerAdmitsExactlyOneCallerThroughProviderHealth
FusionAndReliabilityTests.swift:967: error: ... XCTAssertEqual failed: ("nil") is not equal to
  ("Optional(WebSearchCore.ProviderFailure.FailureCategory.circuitOpen)") - a second caller must
  not join the probe while it is in flight
Test Case '...testHalfOpenBreakerAdmitsExactlyOneCallerThroughProviderHealth' failed (0.083 seconds)
Executed 1 test, with 1 failure (0 unexpected)
```

The second caller was authorised (`nil` = no refusal) while the probe was already in flight.

## The fix

The non-`.open` branch now uses the answer `shouldAttempt()` gives it:

```swift
} else {
    let allowed = await breaker.shouldAttempt()
    if !allowed {
        return ProviderFailure(
            provider: provider,
            category: .circuitOpen,
            message: "\(provider.displayName) is being probed after failures; this request "
                + "is skipped until that probe finishes."
        )
    }
}
```

`.closed` always returns `true`, so a healthy provider sees no behaviour change; `.halfOpen`
now admits exactly one caller and reports the rest as the retryable `.circuitOpen` the
orchestrator already understands. The regression test also pins the recovery path: after the
probe succeeds and the breaker closes, callers are admitted again, so the new refusal cannot
wedge a provider.
