# B25 — an instance's escape sequences reached the operator's terminal

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

`Renderer` interpolated probe-controlled strings straight into the frame, and `mcps-mon`
writes that frame to the tty. A terminal *executes* control characters rather than showing
them, so a SearXNG instance could clear the screen, move the cursor, spoof the window title,
or write the operator's clipboard through OSC 52 using nothing but an engine name:

```swift
// Renderer.swift:305-315 (before)
if let error = node.error {
    detail = Terminal.colour(error, .brightRed, enabled: useColour)      // raw error text
} else if showEngines {
    let healthy = node.engines.joined(separator: ", ")                   // raw engine names
    detail = Terminal.colour(healthy, .grey, enabled: useColour)
    if !node.unavailableEngines.isEmpty {
        let missing = node.unavailableEngines.joined(separator: ", ")    // raw reasons
        detail += "  " + Terminal.colour("unavailable: \(missing)", .brightYellow, enabled: useColour)
    }
}
```

`node.engines`/`node.unavailableEngines` come from the SearXNG JSON (`NodeProbe.swift:104-113`),
`status.lastError` from an error body, and `main.swift`'s warnings quote the same engine names.
Nothing on that path filtered C0/C1: `Terminal.displayWidth` counts C0 as zero width and
`Terminal.truncate` copies characters through.

## The fix

One primitive, applied at the single boundary where untrusted text becomes terminal output:

```swift
// Terminal.swift
public static func sanitize(_ text: String) -> String {
    guard text.unicodeScalars.contains(where: isTerminalControl) else { return text }
    ...
    // every Cc/Cf scalar becomes U+FFFD
}

private static func isTerminalControl(_ scalar: Unicode.Scalar) -> Bool {
    switch scalar.properties.generalCategory {
    case .control, .format: return true    // C0/C1, bidirectional overrides, joiners, BOM
    default: return false
    }
}
```

`Renderer` passes node names, engine names, `unresponsive_engines` reasons, node and provider
error strings, and footer warnings through it *before* styling, so the dashboard's own SGR
sequences are generated after the data and survive. `Cf` is included because those scalars
reorder or hide what the operator sees without occupying a column. The replacement is the
visible U+FFFD, not deletion, so an operator can tell that an instance sent something odd.

`scripts/monitor_tty_smoke.py` gained `check_escape_injection`, which serves a hostile payload
(OSC 52 in the engine name, `ESC[2J` and a bare C1 CSI in the `unresponsive_engines` reason) and
asserts that every escape sequence in the transcript is one the renderer emits itself. This also
covers the `main.swift:431` warning path, which renders through the footer.
