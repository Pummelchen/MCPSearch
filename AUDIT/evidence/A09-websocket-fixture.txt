# A09 — the insecure-websocket finding on a rejection fixture

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13 · semgrep 1.176.0

## What the rule sees, and why it is a false positive

`URLPolicyTests` lists the URLs the policy must **refuse**, and one of them is
a WebSocket-scheme fixture (the exact URL is in the test file) — an insecure WebSocket scheme has to appear in that list, or the test
cannot prove it is rejected. No connection is ever opened: the call under test is
`validateLexically`, which does not touch the network.

```
$ semgrep scan --config=p/default   # before
javascript.lang.security.detect-insecure-websocket.detect-insecure-websocket
   Tests/WebSearchCoreTests/URLPolicyTests.swift:46
```

// Deliberately insecure, and deliberately never opened: this list is the set of URLs

an insecure-WebSocket-scheme URL (scheme `ws`),

reason. The test still runs and still asserts the rejection.
