# B33 — the reader-failure arm of the fallback chain had no test

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

`WebFetcher.performOpen` has four ways out, and the tests covered three: native extraction good
enough, thin native extraction rescued by the reader, and the reader disabled by configuration.
The fourth — **the reader was tried and failed** — had no test, in either of its two shapes:

```swift
// WebFetcher.swift:175-189
} catch {
    log.debug("Jina Reader fallback failed", ...)
    guard let result = directResult else {
        throw directError ?? SearchError.extractionFailed(request.url)
    }
    var finalized = result
    finalized.warnings.append("Jina Reader fallback was unavailable; returned native extraction.")
    return finalized
}
```

A regression here loses either a serviceable page (by throwing instead of returning the native
text) or the fact that the reader was consulted at all (by dropping the warning), and the second
shape hides the *real* reason for a total failure behind a generic extraction error.

## Fails-before evidence

Two mutations of that arm:

```swift
// A. the warning is no longer added
- finalized.warnings.append("Jina Reader fallback was unavailable; returned native extraction.")
// B. the direct error is no longer surfaced
- throw directError ?? SearchError.extractionFailed(request.url)
+ throw SearchError.extractionFailed(request.url)
```

```
$ swift test --filter testAReaderFailure
error: ... the reader failure must be visible to the caller: []            # mutation A
Test Case ... testAReaderFailureWithNoNativeResultSurfacesTheDirectError failed   # mutation B
```

Mutation B is worth a note: the guard it edits appears **twice** in `performOpen` — once for the
reader-disabled path and once for the reader-failure path, with identical body text. The first
attempt at the mutation landed on the reader-disabled copy and proved nothing; targeting the arm
inside `catch` is what falsifies the test. The two tests now distinguish the arms by construction.

## The fix

Two tests in `FetchFallbackTests`:

* a thin native page plus a reader that throws → the native extraction is returned, with the
  `Jina Reader fallback was unavailable` warning, **without** the "used Jina Reader instead"
  wording, and the reader was tried exactly once;
* a direct fetch that fails (503) plus a reader that throws → the caller sees the direct
  `.fetchFailed` naming the 503, not a generic `.extractionFailed`.
