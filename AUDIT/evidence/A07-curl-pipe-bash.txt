# A07 — the Homebrew installer was piped into a shell

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13 · shellcheck · bash 3.2 (macOS)

## What the rule said

`bash.curl.security.curl-pipe-bash.curl-pipe-bash` at `deploy/provision-node.sh:69`:
`NONINTERACTIVE=1 /bin/bash -c "$(curl -fsSL …/install.sh)"`. A pipe runs whatever arrived —
a truncated download, a proxy's error page — and nothing ties those bytes to a reviewed script.

## The fix: a file, a pinned digest, then execution

```bash
HOMEBREW_INSTALLER_URL="https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh"
HOMEBREW_INSTALLER_SHA256="25548e1da7930c1563dbbe2cb05834a4131c4da09234540b6fdac812fda3c287"
installer="$(mktemp -t homebrew-install)"
curl -fsSL "${HOMEBREW_INSTALLER_URL}" -o "${installer}" || fail "could not download the Homebrew installer"
actual="$(shasum -a 256 "${installer}" | awk '{print $1}')"
if [ "${actual}" != "${HOMEBREW_INSTALLER_SHA256}" ]; then
    fail "Homebrew installer digest changed (expected …, got …); review ${URL} and update the pin"
fi
NONINTERACTIVE=1 /bin/bash "${installer}" >/tmp/brew-install.log 2>&1
```

The digest is the entire trust decision, so it is pinned and fail-closed: when upstream
changes, provisioning stops with instructions instead of silently running something new. The
temporary file is removed on every path.

## Verification, and its boundary

```
$ bash -n deploy/provision-node.sh                       OK
$ shellcheck -S style deploy/provision-node.sh          SC2015 x2, SC2016 x2 — identical to the baseline
                                                        (both pre-existing, neither in the new block)

$ curl -fsSL <url> -o <scratch>; shasum -a 256 <scratch>
pin:    25548e1da7930c1563dbbe2cb05834a4131c4da09234540b6fdac812fda3c287
actual: 25548e1da7930c1563dbbe2cb05834a4131c4da09234540b6fdac812fda3c287
PIN MATCHES UPSTREAM

# negative control on the comparison: append one byte to the download
a modified download would be refused (digest 73164b0b… != pin)
```

**Not executed, on purpose:** the provisioning path itself. Running it would install
Homebrew or a Docker runtime and touch the fleet, which the brief forbids, and every node is
already provisioned. The download-and-verify *mechanism* is what is verified above: syntax,
lint parity, the pin matching upstream, and a tampered download being refused. The installer
is fetched and hashed in a scratch directory and never run.
