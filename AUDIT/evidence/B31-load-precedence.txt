# B31 — `AppConfiguration.load` and its precedence had no test

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

```swift
// CoreUnitTests.swift (before)
func testEnvironmentOverridesConfigFile() {
    // Simulated by merging manually: file values first, environment second.
    var merged = AppConfiguration.parseDotEnv("SEARCH_MAX_RESULTS=3")
    merged["SEARCH_MAX_RESULTS"] = "11"
    XCTAssertEqual(AppConfiguration.parse(merged).defaultMaxResults, 11)
}
```

The test named for precedence never called `AppConfiguration.load` — the function the server calls
— and never had a file. It re-implemented the merge inside the test, so the two behaviours that
matter (the environment overriding the file, and the file filling what the environment is silent
about) were both unverified, as was the B09 diagnostics path that only `load` produces.

## Fails-before evidence

Two mutations of `load`, and the old test's blind spot:

```swift
// 1. the environment no longer wins
- for key in Key.allCases { if let value = environment[key.rawValue], !value.isEmpty { values[key.rawValue] = value } }
// 2. the missing-file issue is no longer recorded
- } else { issues.append(ConfigurationIssue(kind: .unreadableConfigFile, ...)) }
+ }
```

```
$ swift test --filter "testEnvironmentOverridesConfigFile|testMissingConfigFileIsReportedAsAnIssue|testConfigFileNamedByTheEnvironmentIsLoaded"
error: ... XCTAssertEqual failed: ("3") is not equal to ("11") - the environment must win
error: ... XCTAssertTrue failed - a missing file must be reported: []
Executed 3 tests, with 2 failures
```

Each mutation is caught by exactly the test that covers it, and the old simulated test would not
have caught mutation 1 at all: it never entered `load`.

## The fix

Four tests in `ConfigurationTests`, using a real temporary dotenv (`FileManager.temporaryDirectory`,
removed afterwards):

* the environment wins over the file, and the file supplies the keys the environment omits;
* `SEARCH_CONFIG_FILE` pointing at a real file is loaded — the documented path;
* a `SEARCH_CONFIG_FILE` that does not exist is reported as `.unreadableConfigFile` for that key;
* a path that exists but cannot be read (a directory) is reported the same way, not treated as an
  empty file.
