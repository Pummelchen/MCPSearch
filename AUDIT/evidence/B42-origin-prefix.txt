# B42 — the hand-rolled `Origin` check accepted any host starting with `127.`

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

```swift
// HTTPMCPHost (before)
private static func isLoopbackOrigin(_ origin: String) -> Bool {
    guard let url = URL(string: origin), let host = url.host() else { return false }
    return host == "127.0.0.1" || host == "::1" || host == "localhost"
        || host.hasPrefix("127.")
}
```

`hasPrefix("127.")` is a *string* test, not an address test: `http://127.attacker.example` passed
it, and that is a name somebody else can register. The check exists because the server has no
authentication, so it is the gate that keeps a browser page on another site from driving it. (The
SDK's `OriginValidator` also refuses such an origin, so this was defence in depth rather than the
only gate — worth stating plainly, because the fix is about the check being correct, not about a
reachable hole in the shipped transport.)

## Fails-before evidence

The check moved into `WebSearchCore` so it can be tested (`Support/LoopbackOrigin.swift`). Putting
the original logic back fails three of the four new tests, the first one being the bypass:

```
$ swift test --filter LoopbackOriginTests
error: ... http://127.attacker.example must be refused
error: ... http://LOCALHOST names this machine          # the old check was case-sensitive
error: ... http://127.1 must be refused                 # the old prefix check accepted this
```

## The fix

```swift
guard let url = URL(string: origin), let host = url.host()?.lowercased(), !host.isEmpty
else { return false }
if host == "localhost" || host == "::1" { return true }

let parts = host.split(separator: ".", omittingEmptySubsequences: false)
guard parts.count == 4, parts.allSatisfy({ UInt8($0) != nil }) else { return false }
return parts[0] == "127"
```

Only `localhost`, the IPv6 loopback literal and dotted-quad literals in `127.0.0.0/8` are accepted.
Alternate spellings of loopback (`http://2130706433`, `http://0x7f.0.0.1`, `http://127.1`) are
refused on purpose: the SDK compares hosts as strings, and resolving them here would widen the
surface for no benefit.

The transport's own test gained the end-to-end case (`Origin: http://127.0.0.1.attacker.example` →
403); the unit tests are what pin the helper, since the SDK validator would also refuse that origin.
