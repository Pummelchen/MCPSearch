# A06 — the secret-scan findings, evidence after the fix

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13 · gitleaks 8.30.1

## Working tree: the tracked content is clean

```
$ gitleaks dir . --redact
leaks found: 1   ->  config.env:20
```

That single hit is the operator's own git-ignored credential file (`config.env`, mode 0600, listed
in .gitignore). Two of its lines contain live-looking credentials; their values are not recorded
here or anywhere else in this repository. The gate for CI therefore scans git-tracked content
(`gitleaks detect`), which does not read ignored files — a `gitleaks dir` run is not a valid
gate and would fail for every operator with a configured local environment.

## The waiver cannot blind the scanner (negative control)

`.gitleaks.toml` keeps the whole default ruleset (`[extend] useDefault = true`) and waives only
the AND of those two paths and that one literal. Control: a scanner-shaped AWS key written to a
path outside the waiver is still reported.

```
$ gitleaks dir <control> --config .gitleaks.toml
findings: 1   ->  aws-access-token  .../control/scripts/control.py
```

The control file was created under ~/Library/Caches/MCPSearch/audit-logs and removed again; it
was never inside the repository.
