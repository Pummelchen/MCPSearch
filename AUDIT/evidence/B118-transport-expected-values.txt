# B118 — the invalid `--transport` error named two of the four accepted spellings

Host: this Mac (arm64, macOS 26.6.2, Swift 6.3.3) · branch audit/2026-09-13

## What was wrong

B114 made `usage` render the `--transport` help line from the `TransportName` table, so `--help`
lists all four accepted spellings. The rejection message did not come along:

```swift
// TransportConfiguration.swift, before
guard let name = TransportName(rawValue: raw) else {
    throw OptionError.invalidValue(
        flag: "--transport",
        value: raw,
        expected: "stdio or http"        // hardcoded, and now the only place that disagrees
    )
}
```

So a caller who mistyped was told the legal set was smaller than it is, and the more natural
`--transport streamable-http` — an alias the parser accepts — looked unsupported.

## The fix

The accepted-value phrase now has one producer, `TransportName.acceptedValues`, rendered from the
same table `parse` resolves against. `usage` and the rejection message both print it, so the
documented set and the error set cannot drift apart again:

```swift
enum TransportName: String, CaseIterable {
    case stdio
    case http
    case streamableHyphen = "streamable-http"
    case streamableUnderscore = "streamable_http"

    /// The accepted spellings as one phrase.
    ///
    /// Both `usage` and the `--transport` rejection message render from this, so the
    /// documented set and the set the error names cannot drift apart. …
    static var acceptedValues: String {
        allCases.map(\.rawValue).joined(separator: ", ")
    }
}
```

The error now reads
`Invalid value for --transport: 'carrier-pigeon' (expected stdio, http, streamable-http, streamable_http)`.
The usage line is byte-for-byte the same phrase. No public signature changed; `acceptedValues` is
internal to `ServerOptions`, and `TransportName` itself is unchanged.

## The assertion

`TransportConfigurationTests.testInvalidTransportIsRejected` pinned the old wording
(`expected: "stdio or http"`). It now pins the full list as a literal, and additionally requires the
same phrase to appear in `--help`:

```swift
let expected = "stdio, http, streamable-http, streamable_http"
assertRejects(["--transport", "carrier-pigeon"], expecting: .invalidValue(..., expected: expected))
XCTAssertTrue(
    ServerOptions.usage.contains("Transport to serve on: \(expected)."),
    ServerOptions.usage
)
```

No new test method was added: the existing rejection test is now strictly stronger, and the B114
lint `testUsageDocumentsEveryFlagTheParserAccepts` still checks each `TransportName` spelling is a
whole token in the usage text.
