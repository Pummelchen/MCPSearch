# B12 — a provider that already failed was charged a second, synthetic deadline

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

`recordBudgetExceeded` decided which providers were still unanswered from
`aggregate.responses` alone. A provider that had already reported a *failure* is not in that
list, so the deadline charged it a second, synthetic `timeout` failure — while the caller, a few
lines above, computed the same set correctly from responses ∪ failures.

Consequences: the provider appeared twice in `providers_failed`, "N provider(s) failed" was
inflated, and `lastError`/`lastErrorCategory` were overwritten with a deadline the provider did
not cause.

## Fails-before evidence

```
$ swift test --filter SearchOrchestratorTests/testABudgetExpiryChargesOnlyTheProvidersThatDidNotReport
  # with the pre-fix derivation restored:
  XCTAssertEqual failed: ("2") is not equal to ("1") - one failure is one report:
    [tavily/serverError "Tavily is temporarily unavailable.",
     tavily/timeout   "Tavily exceeded the search time budget."]
  XCTAssertEqual failed: ("3") is not equal to ("2") - one real failure plus one deadline:
    [tavily, tavily, brave]
```

## The fix

The caller already computes the answered set as responses ∪ failures, so it now passes that set
in — `recordBudgetExceeded(ids:alreadyReported:into:)` — and the duplicated derivation is gone.
The method also returns early when every provider has already reported, so the "budget exceeded"
warning is no longer logged for a deadline that had nothing to cut off.
