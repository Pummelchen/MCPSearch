## Ruff: an explicit, reproducible rule set

`ruff.toml` selects rules explicitly (E, F, W, I, UP, B, BLE, SIM, RUF, PERF, FURB) instead of
inheriting whichever default the installed ruff happens to have — with ruff 0.16.7 the implicit
default reports BLE001/S110/UP041/FURB/RUF findings that an older ruff did not, which is not a
standard a repository can rely on. `S` (bandit) is excluded on purpose and the reason is in the
file: these scripts exist to drive subprocesses, sockets and a PTY, and the security questions
that matter here are covered by the semgrep pass and the Swift SSRF tests.

All 18 findings fixed:

```
  4x EXE001  shebang without the executable bit   -> chmod 755 scripts/*.py
  2x BLE001  blind except                        -> (OSError, ValueError), or a documented noqa on
                                                   the top-level harness handler, whose whole job
                                                   is to report *any* unexpected exception
  2x S110    try/except/pass                     -> contextlib.suppress(OSError, ValueError)
  1x SIM105  try/except/pass                    -> contextlib.suppress(ProcessLookupError)
 10x auto   F541, UP041, FURB167, FURB188, RUF100, FURB110
```

reportMissingTypeStubs off) and both errors it reported were genuine:

2. `monitor_tty_smoke.py:144` overrode `BaseHTTPRequestHandler.log_message(self, *args)`,

## What is still open in this task

`typeCheckingMode` is `standard`, not `strict`. Raising it to strict currently reports **83 errors**:
reportUnknownMemberType 38, reportUnknownArgumentType 19, reportUnknownVariableType 16,
reportUnknownLambdaType 8, reportUnknownParameterType 1, reportMissingParameterType 1 — spread over

and casts where the standard library hands back `Any` (json, subprocess, pty).

The task therefore stays **PROGRESS** rather than DONE: the ruff half and the type-check gate at
`standard` are complete and verified, and the strict upgrade is the remainder of the same task, not a
narrowing of it.

## Strict mode reached (the remainder of this task)

The typing work above was deliberately done so that `strict` would pass, not so that a weaker mode
would: it is annotation and narrowing work, with **no `# type: ignore` anywhere** (the audit brief
forbids them) and no rule disabled. 83 errors became 0 by:

* annotating the one parameter that caused 34 of them — `Session.wait_for`'s `predicate`, a
  `Callable[[Session], bool]` — which let every lambda at its call sites infer;
* giving the JSON receivers a type at the point where the existing `isinstance` guard already
  proved it (`payload_obj = cast("dict[str, Any]", payload)`), instead of leaving pyright to infer
  `dict[Unknown, Unknown]` from `json.loads`;
* typing list elements where the code already filtered them (`blocks`, `pair`, `results`,
  `unresponsive`), and `names` as `set[str]` since it is compared against `REQUIRED_TOOLS`;
* one real robustness improvement forced by the checker: the SSE `content` list is now filtered per
  block (`isinstance(block.get("text"), str)`) rather than assuming every dict's `text` is a string.
