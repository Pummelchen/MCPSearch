# B112 — `statusInput` was the only object schema that omitted `required`

Host: this Mac (arm64, macOS 26.6.2, Swift 6.3.3) · branch audit/2026-09-13

## What was wrong

Every object schema in `Sources/SwiftWebSearchMCP/ToolSchemas.swift` — including every nested
one — declares an explicit `required` list. Only the zero-argument `web_search_status` input did
not:

```swift
// ToolSchemas.swift, before
public static var statusInput: Value {
    [
        "type": "object",
        // A zero-argument tool still declares `properties`. An object schema with no
        // `properties` key at all is rejected by strict validation.
        "properties": Value.object([:]),
        "additionalProperties": false,
    ]
}
```

The comment shows the author was reasoning about strict-validation rules for exactly this schema
and covered `properties` while missing `required`, so the tool advertised a structurally different
contract from every other tool.

The guard that exists to catch this could not: it inferred an absent `required` as the empty set,
then compared it to the (also empty) property set, so the omission was invisible.

```swift
// SchemaCompatibilityTests.swift, before
let properties = Set((object["properties"] as? [String: Any])?.keys ?? [:].keys)
let required = Set(object["required"] as? [String] ?? [])
if properties != required { ... }
```

## The fix

`statusInput` declares both keys, with `required` empty because there is nothing to require. The
file's own header bullet now states the rule for both keys.

```
$ git diff -- Sources/SwiftWebSearchMCP/ToolSchemas.swift
@@ -350,9 +351,12 @@ public enum ToolSchemas {
     public static var statusInput: Value {
         [
             "type": "object",
-            // A zero-argument tool still declares `properties`. An object schema with no
-            // `properties` key at all is rejected by strict validation.
+            // A zero-argument tool still declares `properties` and `required`: an object
+            // schema with no `properties` key at all is rejected by strict validation, and
+            // the schema lint requires every object to carry an explicit `required` list
+            // rather than reading an absent one as empty (ledger B112).
             "properties": Value.object([:]),
+            "required": [],
             "additionalProperties": false,
         ]
     }
```

The structural lint was strengthened rather than duplicated: the same recursive check that already
walks every advertised input and output schema now requires the key to be present, instead of
treating absence as an empty list. The rule is also added to the doc table at the top of the test
file.

```
$ git diff -- Tests/WebSearchCoreTests/SchemaCompatibilityTests.swift
@@ -136,6 +137,13 @@ final class SchemaCompatibilityTests: XCTestCase {
                 if object["additionalProperties"] as? Bool != false {
                     found.append("\(path): `additionalProperties` must be false")
                 }
+                // An absent `required` must not be read as "the empty set": that made a
+                // zero-argument object indistinguishable from one that simply forgot the key.
+                // The contract is about the declared keyword, so every object schema must
+                // carry it, even when there is nothing to require (ledger B112).
+                if object["required"] == nil {
+                    found.append("\(path): object schema without `required`")
+                }
                 let properties = Set((object["properties"] as? [String: Any])?.keys ?? [:].keys)
                 let required = Set(object["required"] as? [String] ?? [])
                 if properties != required {
```

No new test method was added: `testAllAdvertisedSchemasSatisfyCrossClientRules` is the lint that
already walks the real `tools/list` output, and it is now strictly stronger. The advertised schema
is fetched from a freshly started `SwiftWebSearchMCP` over stdio, so the check sees what a client
sees.
