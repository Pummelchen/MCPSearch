# B19 — the budget test never inspected the budget

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

```swift
// SearchOrchestratorTests.testProvidersReceiveALargerBudgetThanTheFinalResultLimit (before)
let capturing = MockSearchProvider(id: .tavily) { _ in
    ProviderSearchResponse(provider: .tavily, results: [oneResult])   // never reads `request`
}
...
// 3 requested results yields a provider budget of 6.
// Verified indirectly: the call succeeds and the provider was invoked once.
XCTAssertEqual(capturing.callCount, 1)
```

`providerResultBudget` is the entire contract the test is named for, and nothing read it. The
mock did not even record the request, so passing `maxResults` instead of the surplus budget
would have kept the suite green — the comment claimed a verification that did not happen.

## Fails-before evidence

Mutation: the orchestrator hands the provider the caller's limit instead of the surplus.

```swift
// SearchOrchestrator.swift:77
- let providerBudget = min(20, max(request.maxResults * 2, request.maxResults))
+ let providerBudget = request.maxResults
```

```
$ swift test --filter testProvidersReceiveALargerBudgetThanTheFinalResultLimit
error: ... XCTAssertEqual failed: ("3") is not equal to ("6")
error: ... XCTAssertGreaterThan failed: ("3") is not greater than ("3") -
  fusion needs more material than the caller asked to return
Test Case ... failed (0.069 seconds)
```

Before the change that mutation passed the test: the assertion was `callCount == 1`, which the
mutated run still satisfies.

## The fix

`MockSearchProvider` now records every `SearchRequest` it is handed (`requests`, guarded by the
same lock as `callCount`), and the test asserts the contract instead of the call:

```swift
let request = try XCTUnwrap(capturing.requests.first)
XCTAssertEqual(request.maxResults, 3)
XCTAssertEqual(request.providerResultBudget, 6)
XCTAssertGreaterThan(request.providerResultBudget, request.maxResults, ...)
```

Recording the request also gives the next test-quality findings (B32's argument validation
among them) a way to assert what a provider actually received.
