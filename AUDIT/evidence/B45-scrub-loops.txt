# B45 — the "prove the scrub" loops proved nothing

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

Both smoke harnesses build the child environment from scratch and then "scrub" it:

```python
environment = {
    "PATH": os.environ.get("PATH", "/usr/bin:/bin"),
    "SEARCH_LOG_LEVEL": "debug",
}
for name in SCRUBBED_VARIABLES:
    environment.pop(name, None)          # never present: the loop is a no-op
```

`environment` is a fresh dictionary, so every `pop` was a no-op — and the monitor script advertised
the loop as "Prove the scrub rather than assume it". The hermeticity guarantee itself does hold
(the dictionary is built from scratch, so an ambient `TAVILY_API_KEY` really cannot reach the
child); what did not hold was the *verification* that claimed to demonstrate it, which is the
difference between a guarantee and a checked guarantee.

## Fails-before evidence

Making the claim real, then breaking it. The mutation adds an ambient-looking key to the fresh
dictionary, which the old loop would have removed (and thus hidden):

```python
environment = {
    "PATH": ...,
    "SEARCH_LOG_LEVEL": "debug",
+   "TAVILY_API_KEY": "tvly-mutation-leak",
}
```

```
$ python3 scripts/mcp_smoke.py <SwiftWebSearchMCP>
AssertionError: the child environment still carries ['TAVILY_API_KEY']
```

## The fix

The loop is replaced by the assertion it was pretending to be, in both scripts:

```python
leaked = set(environment) & set(SCRUBBED_VARIABLES)
assert not leaked, f"the child environment still carries {sorted(leaked)}"
```

(`monitor_tty_smoke.py` raises its own `Failure` instead of asserting, so the harness reports it the
way every other check reports.)
