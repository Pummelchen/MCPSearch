# B98 — the `Monitor` actor's refresh/counting/warning logic had no Swift test

Host: `node1 (arm64, macOS 26.6.2)` · branch `audit/2026-09-13` · Swift 6.3.3

## Premise check: open, but one clause was wrong

The counts were right: `Tests/MCPSMonitorTests/MonitorOptionsTests.swift` (31 tests) covers only
`Options.parse`/`exitCode` and `Tests/WebSearchCoreTests/MonitorTests.swift` covers the renderer and
`NodeStatus`/`ProviderStatus.applying` in isolation. Nothing called the actor's `refresh`,
`buildWarnings` or `waitForNextCycle`; B76 changed the wiring (`probeableTargets`, the `unavailable`
state) and B46 added `exitCode` without adding actor coverage, and
`git log --oneline --all --grep "audit(B98)"` is empty.

**The expected-correct's mechanism was wrong, though.** It says to call
`refresh(forceProbeProviders:)` "with a stub `HTTPClient`", but the actor had no such seam:
`init(options:)` constructed its own `URLSessionHTTPClient` from
`ProviderProbe.buildConfiguration()` — this machine's environment — and there was no initialiser
that took a client. `NodeProbe` and `ProviderProbe` are injectable in the core library, but the actor
did not expose them. Testing through `init(options:)` would have probed whatever the operator has
running and asserted nothing.

## The production change this required (justified)

A test-only initialiser was added to `Monitor`:

```swift
init(options: Options, configuration: AppConfiguration, http: any HTTPClient, log: Log)
```

`init(options:)` now delegates to it, so production construction is unchanged: same
`URLSessionHTTPClient`, same 8 s probe timeout, same `Log(level: .none)`, same registry. The only
other source change is the two stored properties widening from `URLSessionHTTPClient`/inferred `Log`
to `any HTTPClient`/`Log`. The seam is internal, so `@testable import MCPSMonitor` reaches it and
nothing is added to any public surface. Without it the task's own expected-correct is unreachable;
this is the "must say so explicitly" case in the brief, and the alternative — spawning `mcps-mon`
against a stub — cannot drive `refresh(forceProbeProviders:)` or read `buildWarnings`' output
directly, and needs a real listening socket per case.

## What was added

A new `Tests/MCPSMonitorTests/MonitorActorTests.swift` (nine tests) with a URL-keyed
`StubHTTPClient` and a `FailingEndpointClient` that fails one endpoint and delegates the rest.
`MonitorOptionsTests.swift` is untouched at 396 lines; the new file keeps the suite well under
SwiftLint's ceiling.

| Test | Pins |
| --- | --- |
| `testTheFirstRefreshProbesProvidersAndALaterOneDoesNot` | first refresh probes Tavily (`probes == 1`, `.healthy`); a second unattended refresh does not (`probes == 1`) while node checks still advance |
| `testAForcedProbeRunsTheProviderAgain` | a `forceProbeProviders: true` pass takes the counter from 1 to 2 |

## Proof the assertions can fail (mutations of production code)

Three mutations across the two files that own the behaviour, each built with `--build-tests
-Xswiftc -warnings-as-errors` and run with `--filter MonitorActorTests`:

**M1 — the probe gate** (`MCPSMonitor/main.swift`): `hasProbedBefore: !probedProviders.isEmpty` →
`hasProbedBefore: true`, so nothing is ever probed after construction:

```
MonitorActorTests.swift:103: … testTheFirstRefreshProbesProvidersAndALaterOneDoesNot :
    ("Optional(0)") is not equal to ("Optional(1)") - the first pass populates the dashboard
MonitorActorTests.swift:128: … testAForcedProbeRunsTheProviderAgain :
    ("Optional(1)") is not equal to ("Optional(2)") - a forced probe is the operator asking for one
```

**M2 — the counter folding** (`WebSearchCore/Monitor/MonitorModel.swift`): the
`if probe.state == .up { … } else { updated.failures += 1 }` branch removed:

```
MonitorActorTests.swift:177: … testNodeResultsFoldIntoTheCounters :
    ("Optional(0)") is not equal to ("Optional(1)") - a degraded answer is a failed check
MonitorActorTests.swift:198: … testCountersAccumulateAcrossRefreshes :
    ("Optional(0)") is not equal to ("Optional(2)")
```

**M3 — the engine warning threshold** (`MCPSMonitor/main.swift`):
`where count >= max(2, model.nodes.count / 2)` → `where count >= 999`:

```
MonitorActorTests.swift:234: … testWarningsAggregateAcrossNodesAndProviders : XCTAssertTrue
    failed - an engine failing on half the fleet is called out once:
    ["1 node(s) unreachable: node2", "1 provider(s) have no credentials; press p to probe the rest"]
```

## Deviation

The record's "with a stub `HTTPClient`" is only possible after adding an initialiser that accepts
one; `Monitor` had no injectable client. The seam is the same construction the production
initialiser uses, is internal, and leaves `init(options:)`'s behaviour byte-for-byte identical. The
alternative reading — test through `init(options:)` — would have asserted against this machine's
environment and produced a test that cannot fail, which the same brief calls the specific danger.
