# B48 — `provision-node.sh` could not find a Homebrew-installed Tailscale CLI on Apple Silicon

Host: audit workstation (arm64, macOS, bash 3.2, ShellCheck 0.11.0) · branch audit/2026-09-13

## What was wrong

The reachability section at the end of `deploy/provision-node.sh` resolved Tailscale from two
hard-coded absolute paths:

```bash
TAILSCALE_IP="$(/usr/local/bin/tailscale ip -4 2>/dev/null | head -1)"
[ -n "$TAILSCALE_IP" ] || TAILSCALE_IP="$(/Applications/Tailscale.app/Contents/MacOS/Tailscale ip -4 2>/dev/null | head -1)"
```

The first is the Intel Homebrew prefix. The same script's Homebrew section (`:85-90`) applies the
node's own `shellenv`, which on Apple Silicon is `/opt/homebrew/bin`; a formula-only Apple Silicon
node is never looked at. Such a node falls through to the LAN address, or to "neither tailscale nor
a LAN address could be determined" — the misleading outcome the comment above the lookup says sent
operators hunting for a network fault.

## The decision

The finding's expected-correct is to resolve `tailscale` with `command -v` after the script applies
Homebrew's `shellenv`, keeping the app-bundle path as a fallback. That is what the fix does, with
one deliberate addition:

```bash
tailscale_cli() {
    local found candidate
    found="$(command -v tailscale 2>/dev/null)"
    if [ -n "${found}" ]; then
        printf '%s\n' "${found}"
        return 0
    fi
    for candidate in "$@"; do
        if [ -x "${candidate}" ]; then
            printf '%s\n' "${candidate}"
            return 0
        fi
    done
    return 1
}

TAILSCALE_CLI="$(tailscale_cli \
    /opt/homebrew/bin/tailscale \
    /usr/local/bin/tailscale \
    /Applications/Tailscale.app/Contents/MacOS/Tailscale)"
TAILSCALE_IP=""
if [ -n "${TAILSCALE_CLI}" ]; then
    TAILSCALE_IP="$("${TAILSCALE_CLI}" ip -4 2>/dev/null | head -1)"
fi
```

* `command -v` is first, so whichever prefix the node's `shellenv` put on `PATH` wins and no one
  prefix is privileged. The old code privileged `/usr/local/bin`; the finding is that this is the
  wrong one for the fleet's Apple Silicon nodes.
* Both Homebrew prefixes and the app bundle are then tried as explicit fallback *paths*. The finding
  asks the CLI to be found in all three, and `command -v` alone depends on the node's `shellenv`
  having covered the install; the explicit paths are the belt-and-braces form of "all of those".
* The app binary is `Tailscale` (capital T) while the formula's is `tailscale`; spelling each
  candidate path out keeps the app bundle's real name. A rejected first attempt probed a directory
  plus both basenames and printed whichever spelling it tested — on the case-insensitive macOS
  filesystem `[ -x "$dir/tailscale" ]` is true when only `$dir/Tailscale` exists, so it reported a
  filename that is not the one on disk. The explicit-path form avoids inventing a name.
* The helper returns the resolved *path*, not the address, so the discovery can be exercised
  without provisioning a node — the same reason `install_secret_key` was extracted for B17. The
  address is fetched separately and only when a CLI was found; a missing CLI still falls through to
  the LAN address by design, so there is no `|| fail` on this lookup (nothing mutates).

B49's `install_secret_key()` and the settings heredoc are untouched; this change is confined to
`deploy/provision-node.sh:342-375`.

## Verification

The check is a harness at `$HOME/Library/Caches/MCPSearch/check-b48.sh` (outside the repository).
Its fake install locations live under `$HOME/Library/Caches/MCPSearch/B48/fake/` (not `/tmp`, not in
the repository):

```
$HOME/Library/Caches/MCPSearch/B48/fake/opt-homebrew/bin/tailscale                       # Apple Silicon formula
$HOME/Library/Caches/MCPSearch/B48/fake/usr-local/bin/tailscale                         # Intel formula
$HOME/Library/Caches/MCPSearch/B48/fake/path/bin/tailscale                              # a PATH entry
$HOME/Library/Caches/MCPSearch/B48/fake/app-bundle/Tailscale.app/Contents/MacOS/Tailscale
```

Each stub appends its own `$0` to a marker file, so the check asserts on the path the discovery
actually selected, not merely on an address being printed. The harness extracts `tailscale_cli()`
verbatim from the working-tree script for GREEN, and the pre-fix two-line lookup verbatim for RED.

### RED — against the temporarily reverted (pre-fix) code

The hunk was reverted with a file edit (no writing git command was run), the harness was run in
`prefix` mode against that working tree, and the fix was reapplied afterwards.

The row that is the finding is `path:/opt/homebrew/bin`: a stub CLI reachable on `PATH` exactly as
an Apple Silicon node's `shellenv` would expose it, and the pre-fix lookup selects nothing.

Two honest caveats about the RED run. A real `/Applications/Tailscale.app/.../Tailscale` exists on
the audit host, so (a) the pre-fix `none` row is not a genuinely empty machine and passes only
because the selected-path check stays empty, and (b) the pre-fix `fallback:Tailscale.app` row
invokes that real binary rather than the fake stub. The pre-fix code did already handle the app
bundle by hard-coding its path; it is the two Homebrew locations that this finding is about.

### The real call site, not just the helper

The script's own lines (`:352-375`, function and call together) were extracted verbatim and run with
a fake `tailscale` on `PATH` shaped like `/opt/homebrew/bin`:

```
$ sed -n '352,375p' deploy/provision-node.sh > block.sh
$ ( PATH="$HOME/Library/Caches/MCPSearch/B48/fake/opt-homebrew/bin:/usr/bin:/bin" source block.sh; \
      printf 'TAILSCALE_CLI=%s\n' "${TAILSCALE_CLI/$HOME/\$HOME}"; printf 'TAILSCALE_IP=%s\n' "${TAILSCALE_IP}" )
TAILSCALE_CLI=$HOME/Library/Caches/MCPSearch/B48/fake/opt-homebrew/bin/tailscale
TAILSCALE_IP=100.64.0.1
```

`100.64.0.1` is the stub's canned answer, not a node address. The same block with no CLI on `PATH`
selects the app bundle fallback `/Applications/Tailscale.app/Contents/MacOS/Tailscale` (its address
line is omitted here because it is this host's real tailnet address).
