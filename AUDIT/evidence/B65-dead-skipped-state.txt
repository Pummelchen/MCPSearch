# B65 — `NodeStatus.State.skipped` was unreachable

Host: this Mac (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

`NodeStatus.State` carried a fourth case that nothing produced:

```
$ grep -rn "\.skipped\|case skipped" Sources/ Tests/
Sources/WebSearchCore/Monitor/MonitorModel.swift:50:        case skipped          # the declaration
Sources/WebSearchCore/Monitor/MonitorModel.swift:58:            case .skipped: "SKIP"
Sources/WebSearchCore/Monitor/Renderer.swift:30:        case .skipped: Terminal.colour("–", .grey, enabled: useColour)
Sources/WebSearchCore/Monitor/Renderer.swift:65:        case .checking, .skipped: return ...
```

No producer — `NodeStatus.pending` starts at `.checking` and `applying(_:)` takes the state from the
probe result, which is `.up`/`.degraded`/`.down` — and no test constructed one. The monitor's
"deliberately not probed" story is handled a level up: with no nodes to probe the list is empty
(`--no-nodes`, B74), so no row needs a state.

## The decision

Delete the case and its three render branches, rather than invent a producer for a state nothing
needs. The alternative the finding allows — distinguishing an excluded node from one that was never
configured — has no consumer: an excluded node is not in the list at all.
