# B72 — `assertNoCredentialLeak` documented a check it did not perform

Host: this Mac (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

```swift
for request in requests {
    ... headers and body ...
    // A key may legitimately travel in a query string (Mojeek does this),
    // which is exactly why it must never be logged; assert the request was
    // recorded but that our *own* diagnostics never echo it.
}
```

Two problems, one of them in the comment:

* the body scans the mock's **recorded request** headers and body — never a log line, an error or a
  `safeDescription`, which is where a key travelling in a query string would actually surface. The
  comment claimed the helper asserted the diagnostics side;
* there was no guard on an empty `requests`, so a test whose client made **zero** requests passed
  without asserting anything at all.

## The fix

The helper now fails loudly when it has nothing to check, and the comment says what it actually
covers (the mock's recorded traffic) and where the diagnostics side is asserted (the tests that
exercise those paths, such as the Mojeek and error-reporting suites):

```swift
XCTAssertFalse(
    requests.isEmpty,
    "assertNoCredentialLeak needs at least one recorded request: with none it passed "
        + "without checking anything (ledger B72)",
    file: file,
    line: line
)
```

The precondition also makes the helper's call sites honest: a test that stops making requests can no
longer keep "passing" a credential check.
