# B83 — `mcp_smoke.py`'s HTTP wait loop never noticed a dead server

Host: this Mac (arm64, macOS 26.6.2) · branch audit/2026-09-13 · Python 3.14.7

## What was wrong

`free_loopback_port()` binds port 0, reads the number and closes the probe socket before
the child is even started, so the child can lose the race and fail to bind. When it then
exited, `wait_for_health` never called `process.poll()` and never read the captured
stderr: it polled `/health` for the full 20 s and raised a bare

```
HTTP transport did not become healthy on port N
```

The child's stderr was only consumed on the success path, so a startup failure produced a
timeout with no diagnostic. (Pre-fix `wait_for_health` was `scripts/mcp_smoke.py:359-377`;
the only call site was `:407`.)

## The decision

Poll the child on every pass of the wait loop and, once it has exited, fail at once with
the exit code and whatever it wrote to stderr:

```
    exit_code = process.poll()
    if exit_code is not None:
        raise Failure(
            f"HTTP server is not listening on port {port}: it exited with code "
            f"{exit_code} before the transport came up; stderr:\n{child_stderr(process)}"
        )
```

The new `child_stderr(process)` helper does the best-effort read in the same style as
`Server.stderr_text`, including the `OSError, ValueError` guard, and returns a `<...>`
placeholder rather than raising inside a failure path. The original full-timeout message
is kept for the genuinely different case: the child is alive but never becomes healthy.

The expected-correct also offers "keep the probe socket until the child has bound, or
retry a fresh port on bind failure" against the port race. That half was **not**
implemented, deliberately:

- "keep the probe socket until the child has bound" cannot work as written: the child
  binds the port itself, and a socket still bound by the parent makes that bind fail with
  `EADDRINUSE`; `SO_REUSEADDR` does not permit two live binders on macOS. Handing the
  child a pre-bound fd would need a server-side protocol change, out of scope here.
- a retry needs to classify a failure as a bind failure (stderr text matching) and wrap
  `run_http_smoke` in a retry loop — a behavioural change beyond the reported defect.

What the race costs now is bounded and actionable: the run stops in well under a second
and prints the server's own diagnostic instead of a 20 s silence.

## Verification

The check drives the real HTTP path (`run_http_smoke`) with a child that exits 1 without
ever binding — this repository's own smoke script invoked with the HTTP argv (it rejects
`http` as the positional binary path, so that is exactly a startup failure with a
diagnostic on stderr). Nothing ever listens on the chosen port, so the three assertions
are the reported defect: the failure must name the dead server, must carry the child's
stderr, and must arrive well inside the 20 s timeout. RED was captured on the pristine
working tree before the fix and GREEN on the fixed file; the command was identical.

