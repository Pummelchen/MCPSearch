# B95 — the hint test asserted a string the fixture had just constructed

Host: `node1 (arm64, macOS 26.6.2)` · branch `audit/2026-09-13` · Swift 6.3.3

## Premise check: still open after B57

Read B57 first, as the task asked. B57 (`c5280f9`) replaced the five hand-written enablement
mappings with `ProviderEnablement` and rewired `ProviderProbe.setupHint` to read it, and added
`ProbeTests.testSetupHintNamesTheRightVariableForEveryProvider`. It did not touch
`MonitorTests.swift`, where the defect still stood:

```swift
// before — RendererTests.provider(_:state:…), line 148
var status = ProviderStatus.pending(provider: id, configured: state != .notConfigured, hint: "TAVILY_API_KEY")

// before — testUnconfiguredProviderShowsItsSetupHint
provider(.brave, state: .notConfigured, probes: 0, successes: 0)
...
XCTAssertTrue(lines.contains("TAVILY_API_KEY"), "the hint should name the variable")
```

A Brave row was given Tavily's hint by the fixture and then checked for Tavily's variable, so the
test verified only that the renderer echoed the string the test had put there. A renderer printing a
constant `TAVILY_API_KEY` for every unconfigured provider would have passed it.

## The fix — the fixture reads the authority; the test names Brave's own variable

`RendererTests.setupHint(for:)` builds the same `ProviderProbe` the monitor builds
(`ProviderProbe(registry:configuration:)`) and returns `setupHint(for:)`, so every `provider(...)`
row now carries the hint the real authority gives it. The test then asserts:

* the authority's Brave hint is `BRAVE_SEARCH_API_KEY` — a pinned value, not a stub;
* it differs from the authority's Tavily hint, so a constant cannot satisfy the row assertion;
* the rendered row contains `set <authority hint>`;
* the rendered row does **not** contain Tavily's variable — the renderer may not substitute a
  different provider's variable.

The real authority output, not a fixture literal, is the expectation. No production change.

## Not duplicated

`ProbeTests.testSetupHintNamesTheRightVariableForEveryProvider` already pins the authority's
per-provider mapping, including the configuration-dependent `parallel` cases. This test does not
repeat that table: it pins the renderer's consumption of `ProviderStatus.setupHint`, using the
authority only to produce a non-stub expectation for the one provider under test.
