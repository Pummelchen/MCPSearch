# B24 — the cancellation assertion could not fail

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

```swift
// HTTPClientTests.testCancellationPropagatesAsCancelled (before)
case .failure(let error):
    XCTAssertTrue(
        error is CancellationError || (error as? HTTPError) != nil,
        "cancellation must surface as an error, got \(error)"
    )
```

`URLSessionHTTPClient.send` can only throw an `HTTPError` (every failure inside `perform` is
mapped to one) or, from the retry loop's own `Task.checkCancellation()`, a raw
`CancellationError`. So the disjunction was true for every failure the client can produce: the
assertion could not fail, and said nothing about cancellation being reported *as* cancellation.
`web_answer` and the orchestrator branch on `CancellationError`/`.cancelled`, so a
misclassification changes what the caller does.

## Fails-before evidence

Mutation: cancellation is reported as a different category. `HTTPError.isTransient` makes a
transient category get retried and then surface as a raw `CancellationError` anyway, so the
demonstration uses a non-transient one — which is exactly the case that reaches the caller:

```swift
// HTTPClient.from(urlError:) 
- case .cancelled: .cancelled(label: label)
+ case .cancelled: .responseTooLarge(label: label, limit: 0)
```

```
$ swift test --filter testCancellationPropagatesAsCancelled
error: ... XCTAssertEqual failed: ("Optional(HTTPError.responseTooLarge(label: "test", limit: 0))")
  is not equal to ("Optional(HTTPError.cancelled(label: "test"))") -
  cancellation must surface as .cancelled for its own request label, got responseTooLarge(...)
Test Case ... failed (0.325 seconds)
```

The old assertion passes that mutation: `(error as? HTTPError) != nil` holds for
`.responseTooLarge`.

## The fix

The assertion now rejects every category that is not cancellation, while allowing the two
legitimate shapes — the transport's `.cancelled` mapping and the retry loop's raw
`CancellationError`:

```swift
if !(error is CancellationError) {
    XCTAssertEqual(
        error as? HTTPError,
        .cancelled(label: "test"),
        "cancellation must surface as .cancelled for its own request label, got \(error)"
    )
}
XCTAssertEqual(server.requestCount, 1, "a cancelled request must not be retried")
```

The raw-`CancellationError` alternative is kept deliberately: the loop calls
`Task.checkCancellation()` on every iteration, so a cancellation that lands between attempts
legitimately surfaces that way, and pinning the exact case would have made the test
timing-dependent (the class of problem recorded as B35).
