# B78 — `ProviderStatus.State.probing` and `.unavailable` were unreachable

Host: this Mac (arm64, macOS 26.6.2, Swift 6.3.3) · branch audit/2026-09-13

## What was wrong

`ProviderStatus.State` declared six cases, but only four could ever be produced:

```
$ git grep -n -E "case (probing|unavailable)|\.(probing|unavailable)\b" HEAD -- Sources Tests \
    | grep -v unavailableEngines
HEAD:Sources/WebSearchCore/Monitor/MonitorModel.swift:121:        case probing
HEAD:Sources/WebSearchCore/Monitor/MonitorModel.swift:125:        case unavailable
HEAD:Sources/WebSearchCore/Search/ProviderHealth.swift:15:        case probing
```

Every hit on `MonitorModel.probing`/`.unavailable` was the declaration itself. The only producers
of `ProviderStatus` are `ProviderStatus.pending(provider:configured:hint:)`, which starts at
`.configuredButIdle` or `.notConfigured`, and `ProviderStatus.applying(_:)`, which assigns
`.healthy` or `.failing`. Nothing assigns `.probing` (the monitor builds a fresh immutable model
snapshot only *after* all probes return, so it cannot draw an in-flight probe) and nothing assigns
`.unavailable`. The remaining matches are unrelated: `ProviderHealth.Status.probing`
(`ProviderHealth.swift:15`, produced at `:295`) is a different enum, and `unavailableEngines` is a
node field.

The dead cases were not merely inert: `Renderer` implemented a glyph and a state colour for both
(`Renderer.swift:38` `◐`/bright-yellow, `:40` `·`/grey, `:49` bright-yellow `N/A`), so the "N/A"
presentation for an enabled-but-unusable provider looked like working code while being permanently
unreachable.

## The decision

Delete the two cases and their three render branches, rather than invent producers. The finding
allows either; deletion is what the architecture supports today. `.probing` would require the
monitor to publish a partially-updated model mid-cycle, which the "immutable snapshot per refresh"
design deliberately does not do. `.unavailable` has no producer because the condition it describes
— an operator-disabled provider — is exactly what **B76** (still open) is queued to wire up: B76's
`expected-correct` says a disabled provider must be "present[ed] … as unavailable rather than
ready". Deleting the case here removes dead UI surface; B76 owns the producer and can introduce it
with its semantics instead of inheriting a branch that never ran. This is recorded so the two tasks
are not read as contradicting each other.

This is the same call B65 made for `NodeStatus.State.skipped`.
