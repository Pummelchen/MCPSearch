### The one `warning:` line is not a compiler diagnostic

A clean rebuild prints exactly two lines matching `warning:`:

```
warning: 'swiftsoup': skipping cache due to an error: The file "maintenance.lock" doesn't exist.
warning: 'swift-system': skipping cache due to an error: The file "maintenance.lock" doesn't exist.
```

These are **SwiftPM dependency-cache notices**, not compiler diagnostics — the same phenomenon
`AUDIT/environment.md` recorded at baseline. `-warnings-as-errors` exiting 0 is the proof that no
compiler warning was emitted, and the distinction is stated here because the raw grep would
otherwise look like two warnings.

### The written waiver, and why it is narrow

`.gitleaks.toml` carries a waiver for **five synthetic test literals** from commit `41d56935`, an
AND of those two file paths and that exact literal, keeping `[extend] useDefault = true`. The
working tree no longer contains them. This is a documented waiver, not a disabled check: the scan
runs the full history and ruleset and reports zero findings.

The shellcheck notes are **not** waived — they are info-level style notes that A03 deliberately
retained rather than suppressed, and the count is unchanged from A03's record.

## What this does and does not establish

* **Establishes**: the branch builds warning-free and passes its suite on hardware the audit did
  not run on, from a clone with no local state; coverage clears the floor with margin; every
  linter, type checker, secret scanner, CVE scanner and SAST pass is clean or waived in writing;
  the ledger is in a terminal state.
* **Does not establish**: that any vendor MCP client has completed a handshake. That is
  **refused, not pending** — ISSUE-6 was closed as not-planned, and the compatibility claim is
  bounded to the documented strict-mode rules, the schema lint and the local protocol tests.
* **Depends on** the one BLOCKED task: `B122` (cancellation during synthesis is swallowed) is an
  owner decision, recorded rather than resolved unilaterally.

## Repeat-run honesty

The suite was run three times here because a **single** green run has already hidden a real defect
in this audit: `B116`, a local-throttle boundary race that failed about once in twenty runs and
which CI had passed repeatedly. Three consecutive clean runs of 588 tests is stronger evidence
than one, but it is not a proof of absence — the deterministic test B116 added is what actually
pins that race.
