# B01 — the compose secret-key variable, evidence after the fix

Host: MacBook-AB.local (arm64, macOS 26.6.2) · pinned image searxng/searxng@sha256:e084201a… (the digest in deploy/docker-compose.yml)

## What the pinned image actually reads (not upstream master, the image we ship)

```
$ docker run --rm --entrypoint sh <image> -c 'grep -n secret_key /usr/local/searxng/searx/settings_defaults.py'
218:        'secret_key': SettingsValue(str, environ_name='SEARXNG_SECRET'),

# and SettingsValue.__call__ lets the environment override the settings file:
#   94: if self.environ_name and self.environ_name in os.environ:
#   95:     value = os.environ[self.environ_name]
```

So the previously documented `SEARXNG_SECRET_KEY` was inert, and the tracked placeholder in
the mounted settings.yml was the key in force.

## Compose fails closed without a key

```
$ docker compose -f deploy/docker-compose.yml config
exit=1
error while interpolating services.searxng.environment.[]: required variable SEARXNG_SECRET is missing a value: set SEARXNG_SECRET - see deploy/.env.example

$ SEARXNG_SECRET=probe-value docker compose -f deploy/docker-compose.yml config | grep -A3 environment
    environment:
      SEARXNG_BASE_URL: http://localhost:8080/
      SEARXNG_SECRET: probe-value
```

## SearXNG itself fails closed too, and works when keyed

```
$ docker run --rm -v deploy/searxng/settings.yml:/etc/searxng/settings.yml:ro <image>   # no key
exit=1
ERROR:searx.webapp: server.secret_key is not changed. Please use something else instead of ultrasecretkey.

$ docker run -d --name mcps-audit-probe -e SEARXNG_SECRET=probe-value \
    -v deploy/searxng/settings.yml:/etc/searxng/settings.yml:ro -p 127.0.0.1:18888:8080 <image>
$ curl -s -w 'http=%{http_code}' 'http://127.0.0.1:18888/search?q=swift&format=json'
http=200   (21 results, first engine: wikipedia)
```

The throwaway probe container used port 18888 and was removed; the live `mcps-searxng` on
127.0.0.1:8888 was never restarted, touched or removed during this audit.
