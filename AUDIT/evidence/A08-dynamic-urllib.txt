# A08 — dynamic urlopen calls in the two Python harnesses

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13 · semgrep 1.176.0

## What the rule said

`dynamic-urllib-use-detected`, twice: `scripts/mcp_smoke.py` (a `/health` probe built from a port)
and `scripts/searxng_health.py` (a URL built from the operator's `base_url`). The rule's point is
real: `urlopen` also accepts `file://`, so a URL that can be pointed anywhere is a file-read
primitive.

## The fix: assert the destination before opening anything

Both call sites now parse the URL and refuse anything that is not HTTP with a host:

```python
# mcp_smoke.py — the probe is loopback-only, and now says so
health_url = f"http://127.0.0.1:{port}/health"
parsed = urllib.parse.urlparse(health_url)
if parsed.scheme != "http" or parsed.hostname != "127.0.0.1":
    raise Failure(f"refusing to probe a non-loopback URL: {health_url}")

# searxng_health.py — base_url comes from the command line
if parsed.scheme not in ("http", "https") or not parsed.hostname:
    raise ValueError(f"refusing to probe a non-HTTP URL: {base_url!r}")
```

A refused URL is now a clean usage error rather than a traceback:

```
$ python3 scripts/searxng_health.py file:///etc/passwd
INVALID URL  refusing to probe a non-HTTP URL: 'file:///etc/passwd'
exit=2

$ python3 scripts/searxng_health.py --json file:///etc/passwd
{"healthy": false, "reason": "invalid_url", "detail": "refusing to probe a non-HTTP URL: …"}
exit=2
```

## Why the lines also carry a waiver

The rule matches *syntactically* — `urlopen` with a non-literal argument — so a guard cannot
remove the match. Each line therefore carries
`# nosemgrep: dynamic-urllib-use-detected` with the guard immediately above it and the reason in
the surrounding comment. The waiver is one line, the rule stays enabled, and the guard is what
makes the line safe rather than the comment.
