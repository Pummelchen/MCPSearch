# B62 — `isReserved` refused `192.0.0.0/16` while documenting `/24`

Host: this Mac (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

```swift
if a == 192, b == 0 { return true }  // 192.0.0.0/24
```

The test inspects two octets, so it refuses `192.0.1.0/24` … `192.0.255.0/24` — ordinary public
space — while the comment (and the doc block above it) named the IETF-assigned `192.0.0.0/24`.
Either the code or the comment was wrong, and the discrepancy is the kind a reader resolves by
"fixing" the code.

## The decision

The code is kept and the comment corrected, because narrowing the rule would *relax* an SSRF deny
for addresses that no page fetch should reach:

* `192.0.0.0/24` is IETF protocol assignments, `192.0.2.0/24` is TEST-NET-1 and `192.88.99.0/24` is
  the 6to4 relay anycast block — all inside this `/16`;
* refusing the surrounding `/16` errs towards refusal, which is the right direction for this check;
* the audit's rule is that a check is never weakened to make a comment true.

The comment now says which prefix is refused and why, and a test pins it.
