# B43 — the baseline table cited a report that is deliberately not committed

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

`AUDIT/plan.md`'s baseline table named `gitleaks.json` as the artifact for the full-history secret
scan. That file is the raw `--report-format json` output, and it carries the matched values — which
this audit's own rule forbids committing (the findings were five synthetic test literals, waived in
writing in `.gitleaks.toml`). The committed, value-free artifacts are
`AUDIT/baseline/gitleaks-summary.txt` and `gitleaks-stdout.txt`; the table pointed at the one file
that must not exist in the repository, so a reader following it found nothing and could not tell
whether the scan had been run.

## The fix

The row now cites `baseline/gitleaks-summary.txt` and says why the raw report is not committed:

```
| Secret scan, **full history** (gitleaks) | 5 findings, all synthetic test literals |
  `baseline/gitleaks-summary.txt` (the raw `--report-format json` output is deliberately **not**
  committed: it carries the matched values) |
```

## Verification

`ls AUDIT/baseline/ | grep gitleaks` shows `gitleaks-summary.txt` and `gitleaks-stdout.txt`, and the
cited file is tracked (`git ls-files AUDIT/baseline/gitleaks-summary.txt`).
