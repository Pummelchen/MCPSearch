# A05 — swift-nio was the last direct dependency pinned by range

Host: MacBook-AB.local (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

```swift
// Package.swift (before)
.package(url: "https://github.com/modelcontextprotocol/swift-sdk.git", exact: "0.12.1"),
.package(url: "https://github.com/scinfu/SwiftSoup.git",            exact: "2.13.5"),
.package(url: "https://github.com/apple/swift-nio.git",             from: "2.65.0"),
```

Two of the three direct dependencies were exact; the HTTP transport's NIO was a range. The lock
file happens to hold 2.102.0 today, but a `from:` range means a fresh resolve — a new checkout, a
resolved-file regeneration, `swift package update` — can move the transport's networking stack to
an untested release with no change to this repository. The audit's own rule is that a shipped
server runs the graph that was tested.

## The decision

Pin it exactly, like the other two. The alternative — keep the range and rely on
`Package.resolved` plus Dependabot — was considered and rejected: the lock file only binds a build
that keeps it, so the range buys nothing except the ability to move silently, and every dependency
update here is already a reviewed change to a tracked file. Updates remain possible at any time
(`swift package update`, or a Dependabot bump) and now show up as a manifest change plus a lock
file diff, which is what the other two dependencies require.

The reasoning is recorded in `Package.swift` itself, next to the pin, so the next reader does not
have to find this record to know why.

## Verification

```
$ swift package resolve                     # no --scratch-path: see the hazard note below
Working copy of https://github.com/apple/swift-nio.git resolved at 2.102.0

$ git diff --stat Package.resolved          # empty: the pin matches what was already resolved

$ swift build --scratch-path $SCRATCH -Xswiftc -warnings-as-errors                  0 warnings, 0 errors
$ swift build -c release --scratch-path $SCRATCH -Xswiftc -warnings-as-errors      0 warnings, 0 errors
$ swift test
Executed 442 tests, with 6 skipped and 0 failures (0 unexpected) in 17.969 seconds
$ osv-scanner scan source -r .
Scanned .../Package.resolved and found 8 packages — No issues found
```

**Hazard found while doing this (recorded in `AUDIT/environment.md`).** `swift package resolve`
without `--scratch-path` wrote a 974 MB `.build` tree into the repository, which lives inside
Dropbox. It was deleted immediately and the empty `.build` with its `com.dropbox.ignored` marker
restored; every SwiftPM command in this audit now passes `--scratch-path`.
