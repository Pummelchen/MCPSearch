# B71 — three copies of the subprocess harness, folded into one

Host: `node1 (arm64, macOS 26.6.2)` · branch `audit/2026-09-13` · Swift 6.3.3

## Premise check: still open

Confirmed by inspection before touching anything: `StdioServerTests.ServerProcess` (63 lines),
`ErrorReportingTests.Server` (85 lines) and `SchemaCompatibilityTests.Server` (54 lines) were
three copies of the same process + pipe + newline-JSON harness, and they had already diverged.

The `SchemaCompatibilityTests` copy was the worst of the three:

```swift
// before — SchemaCompatibilityTests.swift
init(binary: URL) {
    ...
    process.standardError = Pipe()          // never read by anything
}
func readResponse(id: Int, timeout: TimeInterval = 20) throws -> [String: Any] {
    ...
    if chunk.isEmpty { throw Failure.unexpectedExit }
    ...
}
enum Failure: Error { case timeout, unexpectedExit }   // no stderr payload
```

Measured, not asserted: a child that exits without answering (`/usr/bin/true`) makes the old
harness throw the bare words `unexpectedExit`, while `ErrorReportingTests`' copy — which did
carry the stderr — threw `server exited early; stderr: …`. Both probes are reproduced below.

## The fix — one harness, pure refactor

`ServerProcess` in `TestSupport.swift` is now the only harness:

* one constructor (binary, environment, arguments) with the shared scrub list and
  `ServerTestSupport.childEnvironment` applied exactly as before;
* `send`, `readMessage`, `readResponse` — with the B70 `poll` deadline;
* `call(id:tool:arguments:)`, the convenience only `ErrorReportingTests` had, folded in so that
  file needed no local wrapper;
* stderr captured by a background readability handler for the life of the harness, so the
  divergence above cannot recur: an early exit now reports the child's diagnostics from every
  test file, and a child that writes more than the pipe holds cannot wedge on the write.

`ErrorReportingTests` and `SchemaCompatibilityTests` now say
`private typealias Server = ServerProcess` and keep their local names. Measured against the
previous commit: 150 lines deleted, 96 added (most of them the shared stderr capture and `call`),
for a net −54.

## How equivalence was demonstrated (not asserted)

**1. The pre-refactor tree was built and run side by side.** A detached worktree at `0409a25`
(the commit before this one) was built with its own scratch path, and the same three test
classes were run in both trees through the same runner:

```
$ xcrun xctest -XCTest "WebSearchCoreTests.StdioServerTests,\
      WebSearchCoreTests.ErrorReportingTests,WebSearchCoreTests.SchemaCompatibilityTests" <bundle>
```

Each side's `Test Case … passed/failed/skipped` lines were stripped of timing and sorted into a
manifest; the two manifests are byte-identical:

```
$ diff B71-before.manifest B71-after.manifest
$ echo $?
0
$ wc -l B71-before.manifest B71-after.manifest
      46 B71-before.manifest
      46 B71-after.manifest
```

46 tests, same names, same outcome, 0 failures on both sides — the refactor is behaviour-neutral
for everything the harness serves.

**2. The targeted case where the copies differed proves the unification.** A temporary probe in
`SchemaCompatibilityTests` (removed afterwards) starts a child that exits without answering and
prints the error it gets. Pre-refactor:

```
B71PROBE-EARLYEXIT-BASELINE: unexpectedExit
```

Post-refactor:

```
B71PROBE-EARLYEXIT-AFTER: server exited early; stderr: 
```

Same code path, same timeout, and the diagnostic the finding says was dropped is now present.
The probe was inserted and removed with the file restored byte-identical (`diff` empty; SHA-256
`7493e9ef89e6ff04856dba3a9c51e785ec37b2134b15a683898a9eec9495b53f` for both the restored file
and its backup). The baseline worktree was removed with `git worktree remove`.

**3. A self-inflicted hang was caught and fixed during the refactor.** The first version of the
background stderr capture had `stderrText()` wait unbounded for EOF. `StdioServerTests`
inspects stderr while the child is *still running* (a live MCP session is waiting on stdin), so
the whole class hung — the same failure mode B70 exists to remove, reintroduced by the capture.
The wait is now bounded (`DispatchGroup.wait(timeout: .now() + 2)`), which is enough for the
reader to deliver and cannot hang. This is recorded rather than quietly fixed because it is the
kind of change a "pure refactor" claim usually hides.

## What did not change

No production code. No test assertion, fixture, timeout value or call sequence changed: the
alias keeps `Server(...)`, `readResponse(id:)`, `stderrText()`, `stop()` and `call(...)` spelled
the same at every call site. `SchemaCompatibilityTests`' `advertisedTools()` still starts a fresh
server with a PATH-only environment, exactly as its copy did.
