# B82 — A negative `--queries` silently truncated the query list from the end

Host: this Mac (arm64, macOS 26.6.2, Python 3.14.7) · branch audit/2026-09-13

## What was wrong

`--queries` is a plain `type=int`, so `argparse` accepted a negative count, and the count was
applied with Python slice semantics:

```python
parser.add_argument("--queries", type=int, default=len(QUERIES))
...
queries = QUERIES[: args.queries]
```

`--queries -3` ran the last-but-three prefix, i.e. 48 of the 51 queries, while the header printed
`soak: 48 queries` as though 48 had been requested. `--queries -100` sliced to an empty list, ran
nothing, and still exited 0. The run silently did something other than what was asked for.

```
$ python3 -c "import sys; sys.path.insert(0, 'scripts'); import soak; print(len(soak.QUERIES), len(soak.QUERIES[:-3]), len(soak.QUERIES[:0]))"
51 48 0
```

## The decision

Reject rather than clamp, exactly as the finding's first alternative prescribes. Clamping a
non-positive count to the nearest sensible value would still run a soak the user did not ask for,
which is the defect; an argument error names the mistake before any traffic. The check is
`args.queries <= 0`, not `< 0`, so it matches the required message `--queries must be positive`:
zero is not positive, and a zero-query soak is not a soak — it would reach `run_verdict` and be
reported as `requested provider(s) contributed to no query`, blaming the providers for an empty
request. Both zero and negatives are therefore refused up front. Positive counts, including the
`1` boundary and the default `len(QUERIES)`, are untouched.

The guard sits immediately after `parser.parse_args()`, before the binary is resolved, so it costs
no subprocess and cannot be bypassed by a missing binary:

```python
    args = parser.parse_args()

    # `QUERIES[: args.queries]` with a negative count silently takes queries from the end,
    # so `--queries -3` ran 48 of 51 while the header presented that as the request; a zero
    # count starts nothing. Reject both before the run rather than run a different soak than
    # the one asked for (ledger B82).
    if args.queries <= 0:
        parser.error("--queries must be positive")
```

## Verification

The check drives the real `main()` through `sys.argv` with a deliberately missing binary, so it
exercises argument handling only (no server, no `swift build`) and distinguishes acceptance from
rejection by the message: a rejected count fails at parse time with `--queries must be positive`,
an accepted one reaches `binary not found`. It pins the whole boundary — `-3`, `-100`, `0`, `1` —
not just one symptom.

```

import soak

print("len(QUERIES) =", len(soak.QUERIES), "| old negative slice len(QUERIES[:-3]) =", len(soak.QUERIES[:-3]))

def attempt(count):
    sys.argv = ["soak.py", "--queries", str(count), "no-such-binary"]
    err = io.StringIO()
    try:
        with contextlib.redirect_stderr(err):
            code = soak.main()
```
