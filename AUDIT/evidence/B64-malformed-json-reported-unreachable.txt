# B64 — a non-SearXNG body from a live node was reported as "unreachable"

Host: this Mac (arm64, macOS 26.6.2, Swift 6.3.3) · branch audit/2026-09-13

## What was wrong

`NodeProbe.probe` decodes the response body with

```swift
let payload = try JSONCoding.decoder().decode(SearXNGProbeResponse.self, from: response.body)
```

A failure there throws a `DecodingError`. That is neither a `SearchError` (caught just above)
nor something the HTTP client produces, so it fell through to the generic `catch` and produced
`state: .down, error: "unreachable"`. An instance that answered `200 OK` but served an HTML
error page under a JSON content type, a proxy's own JSON body, or a JSON error object was
therefore displayed as `DOWN / unreachable`. The operator is sent after a network fault that
does not exist — the same misdiagnosis the `403` branch a few lines above exists to avoid.

The 403 case was already classified as `.degraded` with `JSON disabled (add \`json\` to
search.formats)`, so the fix is the same shape one step further down the response path.

## The decision

Catch `DecodingError` separately and report `.degraded` with a parse reason, as the finding's
`expected-correct` asks. `.down`/`unreachable` stays reserved for transport failures, which are
the only thing the generic arm now sees. The two remaining outcomes are deliberate: a real
transport failure is still `.down`, and a response the client itself refused (a `SearchError`
such as an oversized body) keeps its existing `.down` + `safeDescription` treatment.

Latency is reported, because the instance did answer: the `do` block's local `elapsed` is not in
scope in a `catch` clause, so the branch recomputes it from the same `started` value.


## The tests

`Tests/WebSearchCoreTests/ProbeTests.swift` — the old `testMalformedBodyIsDown` pinned the defect
by asserting `.down`, so it is replaced rather than left to contradict the fix. One test covers
both ways the body can be wrong:

* `testMalformedBodyIsDegradedNotUnreachable` — a `200` whose body is not JSON at all
  (`this is not json`). Must be `.degraded`, must carry a latency, and the reason must be the
  parse message.
* `testNonSearXNGJSONIsDegradedNotUnreachable` — a `200` whose body is *valid* JSON of the wrong
  shape (`{"error":"too many requests"}`), which is the sneakier real-world case. Same outcome,
  and specifically never `unreachable`.

`testTransportFailureIsDown` is untouched: it pins that a genuine connection failure still
reports `.down`, so the new arm cannot have swallowed that case.
