# B59 — `PARALLEL_MCP_URL=` could not clear the built-in endpoint

Host: this Mac (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

```swift
// parse(_:)
} else if values[Key.parallelMCPURL.rawValue]?.isEmpty == true {
    configuration.parallelMCPURL = nil
}
```

The branch tests for a *present but empty* value, and `load` never produces one: it copies
environment entries only when they are non-empty (an empty variable is not a setting) and
`parseDotEnv` drops empty values. So the documented-looking way to remove the built-in
`https://search.parallel.ai/mcp` — exporting `PARALLEL_MCP_URL=` — silently kept it, and the branch
was unreachable in production. Parallel is an opt-in aggregator, so an operator who wants it off
had no way to say so short of editing the environment of a different key.

## Fails-before evidence

```
$ swift test --filter testAnEmptyParallelMCPURLRemovesTheDefault
error: ... XCTAssertNil failed: "https://search.parallel.ai/mcp" - an explicitly empty value must clear the default
```

## The fix

`load` carries the explicitly-empty environment value through for this key, which makes the existing
clearing branch reachable:

```swift
if let raw = environment[Key.parallelMCPURL.rawValue], raw.isEmpty {
    values[Key.parallelMCPURL.rawValue] = ""
}
```

It is deliberately this key only: `parallelMCPURL` is the sole setting with a non-nil default that an
operator would want to remove, and widening the rule to every key would turn "unset" into "clear" for
all of them — a different, riskier meaning.
