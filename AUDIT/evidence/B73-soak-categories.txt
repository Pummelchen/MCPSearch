# B73 — the soak report attributed every failure category to every provider

Host: this Mac (arm64, macOS 26.6.2) · branch audit/2026-09-13

## What was wrong

```python
for name, count in failures_by_provider.most_common():
    print(
        f"    {name:16} {count:>3}  (categories: "
        f"{', '.join(sorted({c for c, _ in failures_by_category.items()}))})"
    )
```

`failures_by_category` is the run-wide counter, so the "categories" set printed beside each
provider was the union of every category seen anywhere in the run. A provider that only ever timed
out was reported as also having failed with `server_error` or `rate_limited` if any other provider
did — the opposite of the per-provider attribution the soak exists to produce, and the number an
operator would use to decide which provider to look at.

## The fix

A per-provider counter is accumulated beside the global one and is what the line reads:

```python
categories_by_provider: defaultdict[str, Counter[str]] = defaultdict(Counter)
...
categories_by_provider[failure["provider"]][failure["category"]] += 1
...
f"{', '.join(sorted(categories_by_provider[name]))})"
```

The run-wide summary line below it is unchanged: it is a run-wide line and reads the run-wide
counter, which is correct there.
