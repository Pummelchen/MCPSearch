# B90 — the HTTP listener bounded the request body and nothing else

Host: this Mac (arm64, macOS 26.6.2, Swift 6.3.3) · branch audit/2026-09-13

## What was wrong

`HTTPMCPHost.start` built the server with a backlog, `so_reuseaddr` and an HTTP pipeline. There
was no bound on accepted connections and no read/idle timeout, so a peer that opened connections
and never completed a request held a channel and a descriptor for as long as it liked. The
supported shape is a reverse proxy in front, but `--host 0.0.0.0` is an explicit opt-in and the
class describes itself as "a minimal, correct HTTP/1.1 server", so slowloris-style exhaustion was
available to anyone who could reach the port.

## One premise in the finding is wrong

The expected fix names `ChannelOptions.maxConnections` and `IdleStateHandler`. Neither is
available here:

* a grep over the pinned `swift-nio` 2.102.0 checkout (`grep -rn maxConnections . --include=*.swift`)
  finds no such option at all — it is not a NIO API in this version;
* `IdleStateHandler` lives in `NIOExtras`, which this package does not depend on
  (`Package.swift` lists NIOCore, NIOPosix and NIOHTTP1).

Both bounds are therefore implemented in this file rather than configured. That is a deviation
from the literal spec, not from its intent: the observable requirement is "bound accepted
connections and add an idle/read timeout on the child pipeline".

## The fix

Two bounds, both carried by the child channel.

**A connection bound.** `HTTPMCPHost.maximumConnections = 64`, with a live count in an
`OSAllocatedUnfairLock`. `channelActive` counts the channel and closes it when the count is over
the limit; `channelInactive` releases it (NIO fires `channelInactive` for every channel that
became active, so the count cannot leak). A socket cannot be refused before `accept` without a
custom `ServerSocketChannel`, but a refused connection now costs one descriptor for one
event-loop turn instead of living until the peer gives up.

**A request-completion deadline.** Armed when the channel becomes active — *before* a header is
parsed, which is what covers a peer that trickles a request line — and cancelled when the
request ends:

```swift
func channelActive(context: ChannelHandlerContext) {
    let live = host.registerConnection()
    ...
    requestDeadline = context.eventLoop.scheduleTask(in: timeout) {
        log.warning("Closing an HTTP connection that did not complete a request in time", ...)
        channel.close(promise: nil)
    }
}

case .end:
    // The request is complete. Whatever happens next is a response, and an SSE response
    // is legitimately long-lived, so the idle bound stops applying here (ledger B90).
    requestDeadline?.cancel()
    requestDeadline = nil
```

The deadline is also cancelled in `channelInactive`. The 1 MiB body cap and the single-response
guard are untouched, and the shutdown path is unchanged: `stop()` closes the listener and
`group.shutdownGracefully()` closes the children, whose `channelInactive` releases the count.

## Idle versus streaming, explicitly

The bound is on **receiving a request**, not on the connection's lifetime:

* an idle connection (no bytes at all) never reaches `.end`, so the deadline fires and the
  channel closes;
* a slowloris (partial headers) likewise never reaches `.end`;
* a **streaming response** is a request that already reached `.end`, so the deadline has been
  disarmed before the first response byte. A `GET` that establishes the SDK's standalone SSE
  stream can then stay open indefinitely, which is the legitimate long-lived case the finding
  warned about.

## Configuring the budget

The value is `AppConfiguration.requestTimeout` (default 10 s, `SEARCH_REQUEST_TIMEOUT_MS`),
passed into `HTTPMCPHost` from `main.swift`, so no new configuration surface was added and the
tests can make the bound short. `example.env` now records that the same value also bounds an
incomplete inbound request.

## The tests

Four tests in `Tests/WebSearchCoreTests/HTTPTransportTests.swift`, which drives the built
executable over real loopback sockets (the test target cannot import the executable target).
`RawHTTP` gained descriptor-level helpers (`connect`, `send`, `readHead`,
`waitForEndOfStream`, `closedDescriptors`) because a partial or absent request is exactly what
`request` writes for you; `startServer` gained an `extraEnvironment` parameter.

* `testAnIdleConnectionIsClosedAndTheListenerKeepsServing` — connect, send nothing, expect EOF
  within a 5 s window against a 400 ms budget, then a healthy `/health`.
* `testAPartialRequestIsClosedBeforeItCompletes` — the slowloris shape.
* `testAStandaloneSSEStreamOutlivesTheRequestBudget` — initialize, open `GET /mcp` with the
  session id, read a `200 text/event-stream` head, then assert the peer has **not** closed 2 s
  later (five times the 400 ms budget).
* `testConnectionsBeyondTheListenerBoundAreRefused` — 80 idle connections against a 64 bound:
  at least one must already be closed after 2 s, and the listener serves `/health` again once
  the held peers are released.

## Noted, not changed

* The deadline bounds receiving a request, not a slow *reader* of the response. Backpressure on a
  large response body is NIO's write-buffer story, and the response bodies here are one SSE frame
  at a time; bounding that is a different change.
* A second request pipelined on the same connection (which this server never invites: every
  response sets `Connection: close`) would run without a fresh deadline. The connection is closed
  with the first response, so no such request can be served.
