# B57 — one authority for "which variable enables me", and the `parallel` hint

Host: this Mac (arm64, macOS 26.6.2, Swift 6.3.3) · branch audit/2026-09-13

## The premise, checked first

True, and worse than "triplicated" — the mapping was written out in **five** places, and the
`parallel` entry disagreed between them:

```
$ git grep -n "SEARCH_ENABLE_PARALLEL\|TAVILY_API_KEY\|SEARXNG_BASE_URL" HEAD -- Sources \
    | grep -v AppConfiguration.swift
Sources/SwiftWebSearchMCP/ToolHandlers.swift:396-403      switch, all nine providers
Sources/SwiftWebSearchMCP/main.swift:80-92                startup inventory, all nine
Sources/WebSearchCore/Monitor/ProviderProbe.swift:52-59   switch, all nine
Sources/WebSearchCore/Search/ProviderRegistry.swift:67-69,114,120
Sources/WebSearchCore/Search/SearchPipelineFactory.swift:61-127
```

`parallel` is the provider that needs two inputs. `AppConfiguration.parse` sets
`parallelMCPURL = nil` when `PARALLEL_MCP_URL=` is emptied, and `SearchPipelineFactory` then
registers no adapter, so `ProviderRegistry.select`'s first guard throws
`.notConfigured(.parallel)` while `SEARCH_ENABLE_PARALLEL` may well be `true`. In exactly that
state, `ToolHandlers.unconfiguredHint` and `ProviderProbe.setupHint` both said to set the flag —
advice the operator had already taken — and the startup inventory was the only surface that knew
the endpoint was also required.

The premise is empirically confirmed below: the reverted mapping reproduces
"Set SEARCH_ENABLE_PARALLEL=true to enable the upstream MCP provider." verbatim.

## What was consolidated

One file, `Sources/WebSearchCore/Support/ProviderEnablement.swift`:

* `ProviderEnablement.Input` — one environment variable per case, with `variableName` taken from
  `AppConfiguration.Key` (already the one place a variable is spelled), `assignment`
  (`X` or `X=true`), and `purpose` (the operator-facing clause).
* `inputs(for:)` — the exhaustive provider → inputs mapping. A new `ProviderID` does not compile
  until its requirements are stated.
* `AppConfiguration.satisfies(_:)` — the only place an input is read from configuration.
* `missingInputs`, `inputsToName`, `isSatisfied`, `instruction`, `assignmentList`, `allInputs`.

Every surface now reads it:

| surface | before | after |
| --- | --- | --- |
| `SearchPipelineFactory` notes (feeds `web_search_status`) | six hand-written strings, none for a scraper or `parallel` | `ProviderEnablement.instruction` for every unsatisfied provider |
| `ProviderRegistry.ineligibleReasons` (the string the status tool actually shows) | `"no adapter registered"` | the same instruction, so the status tool and the tool error agree |
| `ProviderRegistry.select` messages | two hard-coded flags | `assignmentList` |
| `ToolHandlers.unconfiguredHint` | nine-case switch | one call |
| `ProviderProbe.setupHint` (the monitor) | nine-case switch | one call |
| `SwiftWebSearchMCP/main.swift` inventory and warning | a nine-row literal table | `isSatisfied` / `allInputs` |
| `SearchOrchestrator`'s no-provider error | two variables of the eight | `allInputs` |

The `parallel` drift is gone by construction: `inputs(for: .parallel)` is
`[.parallelEnabled, .parallelEndpoint]`, so the hint names the endpoint when the flag is on and
the URL is absent, both when neither is set, and names them in that order.

```
$ git grep -n "SEARCH_ENABLE_PARALLEL\|SEARCH_ENABLE_SCRAPERS\|TAVILY_API_KEY\|PARALLEL_MCP_URL" \
      -- Sources | grep -vE "AppConfiguration.swift|ProviderEnablement.swift|Providers/"
Sources/SwiftWebSearchMCP/ToolHandlers.swift:397-398   # prose in a doc comment
Sources/SwiftWebSearchMCP/main.swift:80                # prose in a comment
```

No production string names a provider variable outside the authority any more.

## The tests

* New `ProviderEnablementTests` in `Tests/WebSearchCoreTests/CoreUnitTests.swift` (8 cases):
  every provider names at least one real `AppConfiguration.Key`; `parallel` needs the flag then
  the endpoint; the endpoint-only instruction contains `PARALLEL_MCP_URL` and **not**
  `SEARCH_ENABLE_PARALLEL`; both are named when neither is present; satisfaction tracks every
  input (including the empty-string case); the SearXNG JSON guidance survives; `allInputs` is
  deduplicated in provider order; and the status tool, the factory note and the monitor hint all
  give the endpoint for a flag-on/URL-absent configuration.
* `ProbeTests.testSetupHintNamesTheRightVariableForEveryProvider` keeps every original assertion
  and adds the two `parallel` configurations the finding is about — the assertion was
  strengthened, not deleted.
* New `StdioServerTests.testParallelWithoutAnEndpointIsToldToSetTheEndpointNotTheFlag` drives the
  real server over stdio with `SEARCH_ENABLE_PARALLEL=true` and `PARALLEL_MCP_URL=` and asserts
  the `web_search` error names the endpoint and not the flag.
* `StdioServerTests.testSearchWithoutAnyProviderFailsActionablyRatherThanCrashing` is
  strengthened to require all eight variables, not the two the hand-written message knew.

## Deviation from the spec

None of substance. The expected-correct names three call sites; the consolidation covers five
(the same three plus the registry's ineligible reasons and the orchestrator's no-provider
message), because those two are also operator-facing copies of the contract and leaving them
would have kept the drift alive. `ProviderProbe.setupHint`'s public signature is unchanged; it
is now configuration-dependent, which is required to name the right `parallel` input.
